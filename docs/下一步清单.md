## 5. 发 GitHub Release（给用户下载 lite 用）

### 方式一：手动上传（简单）

1. 确认本机有：`E:\Workspace\webclaw-oss\target\release\webclaw-lite.exe`  
2. 复制并改名：

```powershell
cd E:\Workspace\webclaw-oss
Copy-Item .\target\release\webclaw-lite.exe .\webclaw-lite-windows-x64.exe
Get-FileHash .\webclaw-lite-windows-x64.exe -Algorithm SHA256 |
  ForEach-Object { $_.Hash.ToLower() + "  webclaw-lite-windows-x64.exe" } |
  Set-Content .\webclaw-lite-windows-x64.exe.sha256
```

3. GitHub 仓库 → **Releases** → **Draft a new release**  
4. Tag：`v0.1.0`（新建）  
5. 把 `webclaw-lite-windows-x64.exe` 和 `.sha256` 拖进 Assets  
6. Publish release  

### 方式二：用 Actions（自动）

1. 仓库 Settings → Secrets → Actions → 新建 `NPM_TOKEN`（npm 的 Access Token，权限含 publish）  
2. 本地：

```powershell
cd E:\Workspace\webclaw-oss
git tag v0.1.0
git push origin v0.1.0
```

3. 打开 Actions，等 `release` 工作流变绿  

- [ ] Release `v0.1.0` 已发布  
- [ ] 能下载到 `webclaw-lite-windows-x64.exe`

## 6. 在本机用 DSH 挂上插件验一遍

1. 确认 `examples\cordis.patch.yml` 使用 **`insert:`** 包裹（裸 `- id:` 只会改已有行，会报 `entry "webclaw" not found`），且 `binaryPath` 指向本机 lite。

2. **装进 DSH profile**（`npm install -g` 不够，Cordis 从 profile 的 node_modules 解析）：

```powershell
cd D:\tools\harness-apps\deepseek-harness
pnpm dsh plugin --profile web add @lonk1989/webclaw
```

3. 启动：

```powershell
pnpm dsh web --patch E:\Workspace\webclaw-oss\examples\cordis.patch.yml
```

可用 `--dump-config` 先确认输出里出现 `id: webclaw` / `@lonk1989/webclaw`。

   `webclaw_status` / `webclaw_probe` / `webclaw_run` / `webclaw_freeze` / `webclaw_human_reply` / `webclaw_cancel`  

试跑菜谱：

```text

```

## 卡住时看这里

| 现象 | 处理 |
|------|------|
| `npm publish` 报 scope 无权 | 走上面第 3 步方案 B，改包名 |
| DSH 找不到插件包 | 确认已 `npm install` 到 DSH 能解析的 node_modules / 工作区 |
| `webclaw_run` 失败找不到 exe | 检查 `binaryPath` 是否绝对路径且文件存在 |
| `chromeOk: false` | 安装 Chrome/Edge，或设 `WEBCLAW_CHROME` 指向浏览器 exe |
| Actions 发布失败 | 先用第 4、5 步「手动」路径，不依赖 CI |

更细的发布说明也可对照：[PUBLISH.md](./PUBLISH.md)
